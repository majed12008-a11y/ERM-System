# System Constraint Rules

## Purpose
Store future business constraints that any future system behavior must respect without prescribing implementation.

## Scope
System constraint rules for business limits, required protections, governance invariants, and non-negotiable business expectations.

## What Belongs Here
Approved or candidate system constraint rule files using the assigned constraints number range.

## What Does NOT Belong Here
Technical architecture, implementation constraints, coding rules, or platform-specific requirements.

## Naming Convention
Use `BR-NNNNNN-short-rule-name.md`.

## Review Responsibility
Business Rules Architecture coordinates review with Product Governance and Enterprise Architecture.
